1. Définition du Cloud Computing

Le Cloud Computing (informatique en nuage) désigne l'accès à des ressources informatiques — serveurs, stockage, bases de données, réseaux, logiciels — via Internet, à la demande et avec une facturation à l'usage. Plutôt que de posséder et maintenir une infrastructure physique coûteuse, les entreprises louent ces ressources à des fournisseurs spécialisés.

Cette approche révolutionne la façon dont les entreprises conçoivent leur SI : plus besoin d'investissements matériels lourds, les ressources sont disponibles en quelques minutes, scalables à la demande et facturées uniquement à l'utilisation.

Selon le NIST (National Institute of Standards and Technology) :
"Le cloud computing est un modèle permettant un accès réseau omniprésent, pratique et à la demande à un pool partagé de ressources informatiques configurables qui peuvent être rapidement provisionnées et libérées avec un effort de gestion minimal."

☁️ Les 4 types de déploiement Cloud

🌐

Cloud Public

Infrastructure partagée entre plusieurs entreprises. Exemples : AWS, Azure, GCP. Coût réduit, scalabilité maximale, maintenance assurée par le fournisseur.

🏢

Cloud Privé

Infrastructure dédiée à une seule organisation. Meilleure sécurité et contrôle total. Utilisé chez Thales pour les données sensibles de défense.

🔀

Cloud Hybride

Combinaison cloud public + privé. Flexibilité maximale : données sensibles en privé, charges variables en public. Tendance dominante en entreprise.

🤝

Multi-Cloud

Utilisation simultanée de plusieurs fournisseurs cloud pour éviter les dépendances (vendor lock-in) et optimiser les coûts selon les services.

2. Modèles de service : IaaS, PaaS, SaaS

Le Cloud Computing se décline en plusieurs modèles de service, chacun offrant un niveau d'abstraction différent. Plus on monte dans la pile, moins on gère d'infrastructure soi-même, mais moins on a de contrôle.

🇫🇷 Souveraineté numérique — Enjeu clé chez Thales

Dans le cadre de mon alternance chez Thales, la souveraineté des données est un sujet central. Thales développe des solutions de Cloud de confiance : S3NS (avec Google Cloud) et T-Systems (avec Microsoft Azure). Ces solutions permettent aux entreprises et administrations françaises d'utiliser des services cloud tout en garantissant que les données restent sous juridiction française, conformément au RGPD et aux exigences de sécurité nationale.

Le projet SecNumCloud de l'ANSSI définit un référentiel de sécurité pour les prestataires de services cloud. Thales y participe activement pour proposer des offres qualifiées aux opérateurs d'importance vitale (OIV).

4. Tendances Cloud 2025

Le cloud évolue rapidement. Voici les grandes tendances qui façonnent le secteur en 2025, issues de ma veille continue sur les publications spécialisées.

⚡

Serverless Computing

Exécution de code sans gérer de serveurs. Facturation à la milliseconde. AWS Lambda, Azure Functions, Google Cloud Run. Idéal pour des traitements événementiels et des APIs légères.

🐳

Conteneurs & Kubernetes

Docker pour packager les applications, Kubernetes pour les orchestrer. Standard de l'industrie pour les architectures microservices. Utilisé quotidiennement dans mon alternance.

📝

Infrastructure as Code

Gestion de l'infrastructure via du code versionné : Terraform, Ansible, Pulumi. Reproductibilité totale des environnements, réduction des erreurs humaines.

🤖

IA & MLOps dans le Cloud

Entraînement de modèles IA dans le cloud. SageMaker, Vertex AI, Azure AI. Le MLOps étend les pratiques DevOps aux projets de machine learning.

🔐

Zero Trust Security

"Ne jamais faire confiance, toujours vérifier." Chaque accès est authentifié systématiquement, qu'il vienne de l'intérieur ou de l'extérieur du réseau.

🌿

Green Cloud

AWS vise 100% énergies renouvelables, Google Cloud déjà carbon-neutral. Le FinOps et la réduction de l'empreinte carbone des datacenters deviennent prioritaires.

🌐

Edge Computing

Traitement des données au plus près de la source (IoT, 5G). Réduit la latence et la bande passante. AWS Wavelength, Azure Edge Zones.

💰

FinOps

Pratique pour optimiser les coûts cloud. Chaque équipe devient responsable de ses dépenses cloud. Dashboards de coûts, alertes budget, rightsizing.

🦊 GitLab CI/CD — Mon outil principal chez Thales

GitLab est une plateforme DevOps complète qui intègre le gestionnaire de code source, le CI/CD, le registre de conteneurs et la gestion des tickets. Dans mon alternance, je conçois et maintiens des pipelines .gitlab-ci.yml pour automatiser les déploiements cloud.

Chaque push de code déclenche automatiquement le pipeline : build de l'image Docker, exécution des tests, scan de sécurité, puis déploiement sur Kubernetes après validation manuelle.

# .gitlab-ci.yml — Pipeline Thales (exemple)
stages:
  - build
  - test
  - security
  - deploy

variables:
  IMAGE: registry.gitlab.com/thales/app:$CI_COMMIT_SHA

build-docker:
  stage: build
  script:
    - docker build -t $IMAGE .
    - docker push $IMAGE
  only: [main, develop]

unit-tests:
  stage: test
  image: $IMAGE
  script:
    - pytest tests/ --junit-xml=report.xml
  artifacts:
    reports:
      junit: report.xml

trivy-scan:
  stage: security
  script:
    - trivy image --exit-code 1 $IMAGE

deploy-k8s:
  stage: deploy
  script:
    - kubectl apply -f k8s/
    - kubectl rollout status deployment/app
  environment: production
  when: manual
  only: [main]

🐳 Docker — La conteneurisation

Docker permet de packager une application et toutes ses dépendances dans un conteneur portable et reproductible. Un conteneur fonctionne de manière identique sur n'importe quelle machine, éliminant le problème classique "ça marche sur ma machine".

Contrairement aux machines virtuelles, les conteneurs partagent le kernel du système hôte et sont donc beaucoup plus légers (quelques MB vs plusieurs GB). Ils démarrent en quelques secondes.

# Dockerfile — Application Node.js
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY . .

EXPOSE 3000
CMD ["node", "server.js"]

☸️ Kubernetes — L'orchestration de conteneurs

Kubernetes (K8s) automatise le déploiement, la mise à l'échelle et la gestion des applications conteneurisées. Il garantit que le nombre souhaité de réplicas est toujours en cours d'exécution, gère le load balancing, et orchestre les mises à jour sans interruption (rolling updates).

# Deployment Kubernetes — 3 réplicas avec health check
apiVersion: apps/v1
kind: Deployment
metadata:
  name: thales-app
  namespace: production
spec:
  replicas: 3
  selector:
    matchLabels:
      app: thales-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1
      maxSurge: 1
  template:
    spec:
      containers:
      - name: app
        image: registry.gitlab.com/thales/app:v2.1.0
        ports:
        - containerPort: 8080
        resources:
          requests: { memory: "256Mi", cpu: "250m" }
          limits:   { memory: "512Mi", cpu: "500m" }
        readinessProbe:
          httpGet: { path: /health, port: 8080 }
          initialDelaySeconds: 10
        livenessProbe:
          httpGet: { path: /health, port: 8080 }
          periodSeconds: 30

6. Sécurité dans le Cloud

La sécurité est l'un des premiers freins à l'adoption du cloud, notamment dans les entreprises de défense comme Thales. Le modèle de responsabilité partagée est fondamental pour comprendre qui sécurise quoi.

  RESPONSABILITÉ CLIENT              │  RESPONSABILITÉ FOURNISSEUR
──────────────────────────────────────────────────────────────────
  ✅ Données & chiffrement            │  ✅ Datacenter physique
  ✅ Identités & accès (IAM)          │  ✅ Réseau global
  ✅ Applications                     │  ✅ Hyperviseur
  ✅ Configuration OS & réseau (IaaS) │  ✅ Stockage physique
  ✅ Conformité RGPD                  │  ✅ Serveurs matériels
🔑

IAM — Gestion des identités

Contrôler qui peut accéder à quoi, avec le principe du moindre privilège. AWS IAM, Azure Active Directory, Google IAM. MFA obligatoire pour les comptes admin.

🛡️

Zero Trust

Aucun utilisateur ou service n'est de confiance par défaut, même en réseau interne. Vérification systématique de chaque requête avec des tokens courts.

🔒

Chiffrement

Données chiffrées au repos (AES-256) et en transit (TLS 1.3). Gestion des clés avec AWS KMS, Azure Key Vault, HashiCorp Vault.

🔍

DevSecOps

Intégration de la sécurité dans le pipeline CI/CD : scan SAST, DAST, analyse des vulnérabilités des images Docker avec Trivy ou Snyk.

8. Conclusion

Le Cloud Computing n'est plus une technologie d'avenir : c'est le socle des infrastructures IT modernes. En 2025, ne pas maîtriser les concepts cloud, c'est se priver d'une compétence fondamentale pour tout profil IT — qu'il soit administrateur système, développeur, ou DevOps.
